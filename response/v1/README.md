# Executable Shuffle response integration

This path replaces the historical static-notice concept with actual validation, transactional
SQLite deduplication, and a human-review detach PROPOSAL. No AWS SDK, cloud credentials,
execute mode, or automatic remediation exists. All inputs are synthetic.

Files: policy.py is tested policy; server.py is authenticated TLS API; openapi.json imports
through maintained Shuffle App Creator. shuffle_app.py + api.yaml provide an explicit SDK
adapter where generated action parameter names differ. workflow.json invokes the real
triage_synthetic_alert action with $exec; it is NOT a static notice. It remains unbound because
real app and authentication IDs are generated by the actual Shuffle installation.

## Parent binding and proof

1. Start reviewed response service and prove TLS API with v1.runtime.
2. In private reviewed Shuffle, import openapi.json through App Creator or build the Python
   adapter using its supported walkoff_app_sdk image. No hosted paid account.
3. Configure token and private CA. Never disable TLS verification. Python adapter authentication
   fields are api_token and ca_pem. Workers must resolve response on cloud-response-lab_lab.
4. No Docker socket is mounted here. Parent must supply reviewed isolated Shuffle worker runtime;
   a complete Shuffle control/worker plane is NOT activated or claimed by this build.
5. Bind actual IDs, then import artifacts/v1/shuffle-bound.json:

       python -m v1.shuffle --app-id ACTUAL_APP_ID --authentication-id ACTUAL_AUTH_ID

   Confirm action/parameter names triage_synthetic_alert / alert. Map generated OpenAPI body
   parameters in UI if needed. Explicit Python adapter uses these exact shipped names.
6. Execute with argument containing synthetic=true, rule_id=965a1068-c2bf-4ea5-b1d0-000000000002,
   and event=<attack CloudTrail record from artifacts/v1/cases.json>. Replay the same argument.
   Save complete execution results: human_review_required then duplicate, with actions empty.
   If API proof consumed it first, both are duplicates; use a fresh synthetic eventID for demo.
7. Submit denied/foreign/stale events; capture failures. Export bound workflow and execution
   evidence to artifacts/v1. Unit tests do NOT satisfy Shuffle runtime proof.

Shuffle engine. No claim that Shuffle ran, a Kibana screenshot exists, or live end-to-end is done.
