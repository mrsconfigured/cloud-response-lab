# AWS pack (CloudTrail)

Owner lane: **detection**. Log source: AWS CloudTrail, delivered to S3 and loaded into `logs-cloud-response-lab-library-aws`.

| Piece | Where |
|---|---|
| Sigma rules | `detections/*.yml` |
| Playbooks (response as code) | `playbooks/*.json`, with the generated Shuffle workflow beside each as `*.shuffle.json` |
| Tests | `tests/` (two lines each: they call the shared kit in `core/testkit.py`) |
| ATT&CK layer | `attack-layer.json` (generated by `python -m library.build`) |
| Console wiring | `pack.json`: field mapping, Kibana data view, action buttons, which rules are enabled |

## Rules (5)
Console login without MFA, CloudTrail logging stopped, CloudTrail trail deleted, IAM access key created, IAM AdministratorAccess attached.

## Playbooks (dry-run only)
`contain-iam-user`: asks for approval, then simulates deactivating the user's access keys and attaching a DenyAll policy. It no-ops on service-initiated events, failed calls and protected principals.

## Attack simulation principal
The lab's attack-simulation IAM user is the documented Stratus Red Team principal. Stratus needs those permissions, so it is **intentionally privileged** and is never used for ingestion. It was created from a console session without MFA; that is recorded as a finding, not an oversight.

## Adding a log source
Copy this folder shape. A new pack needs `pack.json`, `detections/`, `playbooks/`, `tests/` and a README. The console, CI and metrics read `pack.json` and need no code change.

## Ingestion (scheduled, read-only)
`ingest/cloudtrail.py` runs on a schedule, pulls the last two days of CloudTrail objects and loads them idempotently (document id = `eventID`). It uses a dedicated IAM user that can only list and read the trail prefix. Policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {"Sid": "ListTrailPrefixOnly", "Effect": "Allow", "Action": "s3:ListBucket",
     "Resource": "arn:aws:s3:::<trail-bucket>",
     "Condition": {"StringLike": {"s3:prefix": ["AWSLogs/<account-id>/CloudTrail/*"]}}},
    {"Sid": "ReadTrailObjectsOnly", "Effect": "Allow", "Action": "s3:GetObject",
     "Resource": "arn:aws:s3:::<trail-bucket>/AWSLogs/<account-id>/CloudTrail/*"}
  ]
}
```
Checked against this policy: listing and reading the trail succeed; writes, deletes, listing other prefixes or buckets, IAM, CloudTrail and EC2 calls are all denied.
